# 서브 에이전트 · 오케스트레이션

> 한 세션이 다른 세션을 **자식(하위 에이전트)** 으로 띄워 일을 나누는 기능입니다.  
> 실제 패턴(병렬, 파이프라인, Org 팀 등)은 번들 **오케스트레이션 스킬**로 고릅니다.

---

## 서브 에이전트란?

|                   | 설명                                                                                                             |
| ----------------- | ---------------------------------------------------------------------------------------------------------------- |
| **무엇인가**      | 부모 세션이 `agent__spawnSession` 등으로 만든 **자식 세션**. 부모–자식 **계보(lineage)** 가 남습니다.            |
| **무엇이 아닌가** | 부모 런타임을 복제한 클론이 **아닙니다**. 워크스페이스·로컬 스킬·`agents.md`가 자동으로 복사되지 않습니다.       |
| **누가 쓰나**     | 보통은 사용자가 직접 툴을 부르기보다, `@skill:delegate` 등 **오케스트레이션 스킬**을 붙여 에이전트가 관리합니다. |

부모는 먼저 기존 자식 중 같은 assistant 설정의 **Idle 세션을 확인**하고, 적합하면 `messageToSession`으로 재사용합니다. 적합한 세션이 없거나 다른 역할·병렬 처리·격리 workspace가 필요할 때만 자식을 **시작 → 폴링/`checkSession` → `messageToSession`으로 보정 → 결과 병합**합니다.
형제 세션끼리는 직접 대화하지 않습니다(허브인 부모가 중계).

### UI에서 보는 곳

| 화면                      | 내용                                                                             |
| ------------------------- | -------------------------------------------------------------------------------- |
| **Chat / 세션 히스토리**  | 세션 카드에 하위 에이전트 개수. 삭제 시 **자식 포함 삭제** vs **자식 유지** 선택 |
| 사이드바 **Org** (`/org`) | **명시적 Org** 로 만든 팀만. 일회성 위임 세션은 여기 안 나옵니다                 |

## 꼭 기억할 격리 규칙

자식 세션은 기본적으로 **자기 워크스페이스**를 씁니다.

- 워크스페이스 지시(`agents.md` / `AGENTS.md` / `CLAUDE.md` / `GEMINI.md`)와 workspace 스킬은 **자식 쪽**에서 읽힙니다.
- **assistant** scope 스킬은 자식에 고른 어시스턴트 기준입니다.
- **global** 스킬은 부모·자식 모두 쓸 수 있습니다.
- 같은 폴더에서 작업해야 하면 스킬/에이전트가 `workspaceOverride`로 경로를 지정합니다(기본 복사가 아님).
- `messageToSession(reset=true)`는 이전 대화·계획·대기 메시지와 런타임 상태를 초기화하지만 workspace 파일은 지우지 않습니다. 브라우저 세션도 종료되므로 이전 브라우저 상태가 필요하면 `reset=false`를 사용하세요.

부모가 임시로만 가진 파일·로컬 `skills/`·워크스페이스 규칙을 자식이 “당연히” 안다면 위임이 실패하기 쉽습니다. 핸드오프에 **목표·범위·산출물 형식·필수 경로**를 적거나, 공유 워크스페이스/`workspaceOverride`를 쓰세요.

자세한 툴 이름·트러블슈팅은 번들 `@skill:delegate` 본문을 따릅니다.

## 언제 어떤 스킬을 쓰나

입력에 `@skill:이름`을 붙이거나, 에이전트에게 패턴 이름을 말해 주세요.

### 1) 한 번 위임 · 기본 오케스트레이션

| 스킬           | 이럴 때                                                                        |
| -------------- | ------------------------------------------------------------------------------ |
| **`delegate`** | 자식 세션 생성·감시·추가 지시·워크스페이스 격리의 **기본기**. 다른 패턴의 전제 |
| **`recruit`**  | 새 **전문 어시스턴트 설정**을 만들고 싶을 때 (세션 위임 자체는 아님)           |
| **`boost`**    | **이미 있는** 어시스턴트 도구를 정리·보강할 때                                 |

```
@skill:delegate
이 리포의 auth 모듈만 읽고 취약점 후보를 Markdown으로 요약해줘.
```

### 2) 작업 나누기 패턴 (일회성 자식 세션)

| 스킬                       | 패턴        | 한 줄                                                       |
| -------------------------- | ----------- | ----------------------------------------------------------- |
| **`divide-conquer`**       | 병렬 분할   | 겹치지 않는 조각을 여러 자식에 나눠 합침                    |
| **`hub-spoke`**            | 허브–스포크 | 중앙 코디네이터가 워커만 지휘·병합 (워커 간 직접 통신 없음) |
| **`pipeline`**             | 순차 조립   | A 산출 → B 입력 → C … (연구→초안→리뷰 등)                   |
| **`consensus-delegation`** | 다관점 합의 | **같은 질문**을 2–4 전문가 자식에게 → 부모가 충돌 조정      |
| **`gatekeeper`**           | 품질 게이트 | Creator ↔ Reviewer 루프 (재작업 횟수 제한)                 |
| **`pair-programming`**     | 페어        | Driver / Navigator가 **공유 워크스페이스**에서 턴제         |

```
@skill:divide-conquer
프론트·백엔드·문서 점검 리포트를 병렬로 나눠 작성한 뒤 하나로 합쳐줘.
```

```
@skill:consensus-delegation
이 PR의 보안·성능·유지보수 관점을 각각 검토하고 의견을 조율해줘.
```

### 3) 지속 팀 · Org (명시적 조직)

일회성 위임과 다릅니다. **팀 구성물(미션·역할·조율 파일)** 과 **Org UX**가 필요할 때입니다.

| 스킬                  | 역할                                                              |
| --------------------- | ----------------------------------------------------------------- |
| **`teamwork`**        | 태스크포스 설계·아티팩트 디렉터리·조율 모델 선택. **먼저** 준비   |
| **`org`**             | `agent__createOrg` 후 Org에 보이는 멤버 세션. 재개는 **Org 루트** |
| **`org-restructure`** | 이미 있는 Org의 역할 추가/정리·헌장(`agents.md` 등) 수정          |

흐름 요약: `teamwork`로 스캐폴드 → `org`로 조직 생성·멤버 스폰 → 사이드바 **Org**에서 루트 재개 → 구조 변경은 `org-restructure`.

- **Org** ≠ 예약 자동화(`schedule`) ≠ 세션 안 리마인더(`session-schedule`)
- 일반 부모–자식 위임만으로는 **Org** 목록에 안 뜹니다

```
@skill:teamwork
리서치·구현·리뷰 3역할 태스크포스를 만들고 hub-spoke로 조율해줘.
```

## 빠른 선택 표

| 하고 싶은 일                    | 추천                               |
| ------------------------------- | ---------------------------------- |
| 한 자식에게 맡기고 결과만 받기  | `@skill:delegate`                  |
| 큰 일을 독립 조각으로 병렬 처리 | `@skill:divide-conquer`            |
| 중앙이 여러 워커를 배분·통합    | `@skill:hub-spoke`                 |
| 단계가 순서대로 이어짐          | `@skill:pipeline`                  |
| 같은 안건을 여러 관점으로       | `@skill:consensus-delegation`      |
| 작성 ↔ 엄격 리뷰 루프          | `@skill:gatekeeper`                |
| 두 에이전트가 코드 페어         | `@skill:pair-programming`          |
| 오래 가는 팀 + Org 화면         | `@skill:teamwork` → `@skill:org`   |
| 전문 어시스턴트 새로 뽑기       | `@skill:recruit` (이후 `delegate`) |
| 기존 어시스턴트 도구 다이어트   | `@skill:boost`                     |

스킬 scope·설치 일반론은 [스킬 가이드](skills.md)를 보세요.

## 사용 팁

1. **가장 작은 구조**부터 — 한 에이전트로 되면 팀을 만들지 마세요 (`teamwork`도 같은 원칙).
2. **핸드오프를 자급자족**으로 — 자식이 부모 대화를 추측하지 않게.
3. **기본은 비동기 스폰** — 부모가 다른 일을 할 수 있으면 병렬 패턴에서 `waitForResult=false` 쪽이 일반적입니다(스킬이 안내).
4. **자식 결과를 검증** — 경로·범위·누락된 workspace 규칙을 확인한 뒤 최종 답으로 제시.
5. **세션 삭제** — 히스토리에서 하위 에이전트 포함 여부를 확인하세요.
